# OWASP Top 10 (2021) — release checklist for shop-secure

Every row names the control in this project and the evidence that it works: a test that runs on
`./mvnw verify`, or a transcript in [security-session.md](../security-session.md). The two rows
without a control (A06, A10) state the gap and the planned mitigation.

## Known limits accepted for this release

- **Lockout can be used to deny service.** Anyone can lock a known username for 15 minutes with 5
  wrong passwords. The rate limiter slows this down; a CAPTCHA or exponential back-off per IP would
  be the next step if it is abused.
- **Rate limits and lockout counters are per instance.** `LoginRateLimiter` is in memory. With more
  than one instance it needs a shared store (Redis, or Bucket4j with a JCache/Redis backend). The
  limit is per client IP as seen by the server; behind a proxy, configure
  `server.forward-headers-strategy` for the trusted proxy only, never trust `X-Forwarded-For` blindly.
- **Access tokens cannot be revoked before they expire.** Logout and reuse detection revoke refresh
  tokens; an access token that was already issued stays valid for at most 15 minutes. Role changes
  take effect with the next login or refresh.
